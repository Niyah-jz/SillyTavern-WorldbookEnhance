# 双端酒馆原生功能优化（SillyTavern 扩展）

在酒馆**原生的界面**里做双端增强：世界书面板、全局世界书预设与分类、条目整理、对话正文双击编辑。手机端与电脑端同一套界面，删掉目录即复原。

- 仓库：https://github.com/Niyah-jz/SillyTavern-WorldbookEnhance
- 作者：niyah_jz
- 许可：AGPL-3.0（见 LICENSE）
- 实测环境：SillyTavern 1.18.0；Android Chrome / Via（WebView 内核，红米 K70）；Windows Chrome

## 它做什么

**世界书 · 全局这一层**

- 「已启用世界书」换成可搜索列表：点名称直接跳去编辑那一本；✕ 停用要连着点两下才生效——结构上没有「误触一下就取消启用」这回事
- 「＋ 添加」只列还没启用的书，点一下即启用、就地打勾
- 整本书收藏（★）、只看收藏、收藏置顶
- **全局世界书预设**：把「现在启用了哪几本全局世界书」存成一套，之后一键整套切换；空的一套也能套用（＝一套都不启用）；可改名、覆盖、删除，还能按自定义分组收纳（组名自己定）
- **世界书分类**：按全量绑定关系把书分进 角色卡 / 附加 / 人设 / 聊天 / 全局 / 未绑定 五组，两段展示；书名搜索即时生效，条目标题搜索会先把每本书的条目标题建成本地索引再搜；「未绑定」可勾选批量删除（两段确认，删的是磁盘文件、不备份）

**条目**

- 收藏条目（☆/★，不是收藏书）：可「仅收藏」筛选，可「收藏置顶」
- 只读预览（👁）：主要关键词 / 逻辑 / 可选过滤器 / 正文，不打断编辑
- 批量操作：条目多选（可搜备注名/关键词/正文）→ 移动到/复制到另一本书；批量删除（可从操作历史恢复）；批量开关递归两项
- 批量替换：备注名 / 关键词 / 正文三面可选，先预览命中数与样例，执行后记录可撤销
- 递归设置：一键给整本书开关「不可递归 / 防止进一步递归」，可撤销
- 条目体检 BETA：中文逗号、关键词重复、超长关键词、只填可选过滤器没主关键词、正文为空、触发概率 0、at Depth 没填深度、备注名重复、「递归两项都没开」；能自动修的只有安全的两类（拆中文逗号、去重），每条可单独「本机忽略」
- 操作历史：移动/复制、启用/停用、删除（带原文可恢复）、替换/关键词整理、递归开关都能撤销
- 字段防误触：条目内的文本框与数字框默认只读，双击那个字段才解锁，解锁后「取消 / 保存」出现在右侧，列表同一时刻只允许一处处在编辑状态

**筛选与搜索**

- 触发策略筛选（常量 / 正常 / 向量化）、只看已禁用、仅收藏——覆盖全库，不是只筛当前页
- 条目搜索的「搜索范围」三键：标题 / 关键词 / 正文（三面全开＝原生行为）

**手机端**

- 出现的原生下拉（插入位置、关键词逻辑、条目状态、大小写 / 整词 / 分组计分）一律换成自绘浮层，不再弹系统选择器
- 世界书选择排、五个宿主图标排成两排；工具条也分两排，不横滑
- 电脑端的「条目排序」「每页条目数」保留宿主原生下拉，只加双击解锁（第一下拦下并提示，第二下才真正打开）

**对话**

- 双击消息正文＝点那颗铅笔；编辑期间消息右下角再挂一排同样的按钮（确认 / 复制 / 删除 / 上移 / 下移 / 取消），顶部那排照旧保留

**扩展设置**

- 扩展程序页里有「双端酒馆原生功能优化」抽屉，顶上总开关：勾掉就回原生酒馆，各项状态保留，重新勾上即恢复

**通用**

- 所有控件跟随酒馆主题变量，换主题不会像外挂
- 数据存在酒馆本地设置里（`extension_settings.worldbookMobileEnhance`，落在 `data/<user>/settings.json`），电脑与手机共用一份，换浏览器 / 清缓存不丢
- 版本自动重载：页面加载后核对一次版本，文件已更新就提示并重载，不用手动硬刷新

## 安装

1. 酒馆 → 扩展（拼图图标）→ **Install extension**
2. 粘贴仓库地址：`https://github.com/Niyah-jz/SillyTavern-WorldbookEnhance`
3. 刷新页面（Ctrl+Shift+R）

要求 SillyTavern **1.18.0 或更新**（依赖 1.18 的世界书接口与面板 DOM）。

## 更新

同一页面里点该扩展的「更新」（酒馆执行 git pull），刷新即可。手机与电脑访问同一实例时，更新一次两端同时生效。

## 装好之后在哪用

- **世界书面板**（右上角书堆图标）：顶部多出筛选条和两组按键——「批量整理」＝批量替换 / 批量操作 / 递归设置；「检查记录」＝条目体检 / 操作历史。手机端「已启用的世界书」变成可搜索列表，「＋ 添加」只列未启用的书。
- **「Active World(s)」下面**：一行「全局世界书预设 [当前那套 ▾] [存为预设]」；点开浮层可整套切换，每行右侧有 分组 / 改名 / 覆盖 / 删除。
- **分类按钮**（世界书选择排里的那个）：按全量绑定关系分组浏览、搜索、批量删除未绑定的书。
- **条目右侧**：☆ 收藏 / 👁 只读预览 / ⇄ 移动或复制 / 📋 复制 / 🗑 删除；手机端这几个键排在条目右下角。
- **条目搜索框右边**：搜索范围三键（标题 / 关键词 / 正文）。
- **扩展程序页**：本扩展的抽屉里是总开关与各功能的说明。

## 数据与隐私

- **不发起任何第三方网络请求**：没有 CDN、没有遥测、没有外部字体或图标，代码里没有任何外部域名。
- 与酒馆的交互只走它自己的同源接口（读/写世界书 `loadWorldInfo` / `saveWorldInfo`，保存设置 `saveSettingsDebounced`）。
- **不收集任何信息**，不上传任何内容。
- 本扩展自己的持久化数据都写在 `settings.json` 的 `worldbookMobileEnhance` 键下，用户可随时在界面里清掉：
  - `favBooks` / `favPin`：收藏的整本书与「收藏置顶」开关
  - `favEntries` / `entryFavPin`：条目收藏与「收藏置顶」开关
  - `presets` / `presetGroups` / `customBooks`：全局世界书预设、预设分组、「自定义」那一套的书名
  - `history`：操作历史（含被删条目原文，用于恢复；上限 300 条 / 约 7.8MB，超了先淘汰最早的；可在「操作历史 → 清空历史」一键清空）
  - `healthIgnore`：体检里被忽略的条目
  - `searchScope`：搜索范围三键的开关状态
  - `enhanceEnabled` 等少量开关：总开关与各功能开关
- 卸载后这些键会留在 `settings.json` 里（不影响使用），需要彻底干净可手动删除 `worldbookMobileEnhance` 这个键。

## 实现方式与边界

- 不改酒馆任何源码文件，也不往酒馆目录里写数据文件。
- 接管方式：在运行时包一层宿主的 `worldInfoFilter.applyFilters`（筛选覆盖全库）、监听 `#world_popup_entries_list` 的子节点变化（重绘后重新挂按钮）、按 ST 的行号契约读取 DOM 与写回世界书。
- 每处依赖都有 `typeof` 守卫与 try/catch：宿主升级导致接口/类名变化时，对应功能会**降级或静默消失**，不会把面板弄坏（原生世界书始终可用）；接管失败时容器上没有 `data-wbm-ready`，CSS 也不生效，界面直接退回原生。
- 手机键盘卡顿：Android 上会压住酒馆 `browser-fixes.js` 里「每次 resize 把 `<html>` 设 fixed 再还原」的 hack（每次键盘弹收会强制两次整页重排）；iOS 不动它，因为那段本来是修 iOS 的错位问题。
- 无轮询、无 `setInterval`；只有按需的事件钩子与一次性观察器。

## 兼容性

- **跨设备（手机与电脑访问同一个酒馆实例）**：本扩展不保存任何浏览器侧数据（localStorage 只在拿不到宿主接口时兜底）。收藏、预设、操作历史、体检忽略、搜索范围全部写在酒馆服务端设置 `data/<user>/settings.json` 的 `worldbookMobileEnhance` 键下——电脑上标的收藏，手机刷新就在；反过来也一样。两边同时改同一本世界书时，遵循酒馆自身的「最后保存者胜」语义（不做冲突合并）。
  让手机连上同一个实例用的是**跨设备访问助手**（`sillytavern-cross-device-access-helper`，作者 adelia1017，版本 0.4.0 / main-895455a），本机装在 `data/<user>/extensions/` 下（just-for-me 安装位，不在 third-party），日常与电脑、手机一起在用，共存正常、不冲突：它的作用是把服务器局域网地址找出来、备份并改/恢复 `config.yaml` 的 `listen` 与 `whitelistMode`，可选生成二维码；它的样式全部限定在 `.cross-device-access-helper*` 类名下，不碰世界书面板的任何选择器。
- **鸡尾酒（cocktail-plus）**：服务端插件，本机实测共存正常。它的 `/api/settings/save` 默认开 patch 模式，本扩展写设置走的是宿主的 `saveSettingsDebounced`，只会把差异写回去；它的模块代理显式排除 `/scripts/extensions/third-party/`，不会改写本扩展的代码。
- **悬浮类世界书插件**（世界书悬浮管理 / 管理器 / Explorer 一类）：不冲突。本扩展不提供悬浮入口，所有界面都在酒馆原生界面内部，与它们共存不抢入口。
- **唯一需要留意的冲突面**：如果另一个扩展也替换宿主的 `worldInfoFilter.applyFilters` 且不做链式调用，两者只能有一个生效（后装的生效）。除此之外本扩展不占用任何共享状态。
- **文本改写类扩展**（如 Veridis-Rewrite）与本扩展没有交集。

## 已知限制

- 兼容性按 **1.18.0** 实测；更老的版本未测试，可能部分功能降级。
- 体检只自动修安全的两类（中文逗号、重复）；「递归两项都没开」只提示，不自动判断。
- 「条目标题搜索」每个会话第一次切到该模式时要把全库条目标题读一遍（约一千本量级十几秒，带进度），索引只在内存里，刷新后重新建。
- 双窗口/双设备同时改动同一本世界书时，酒馆本身就是「最后写者胜」，本扩展沿用该语义。

## 卸载

删除 `public/scripts/extensions/third-party/<本扩展目录>`（或在酒馆扩展面板点删除）→ 刷新。界面即恢复原生，`settings.json` 里那个键可留可删（见上一节）。

## 更新日志

- **1.1.0** 从「只改世界书」扩到双端整体：世界书选择排与工具条重排、手机端原生下拉全部换成自绘浮层、全局世界书预设（整套切换、空集、分组、改名/覆盖/删除）、按全量绑定关系的世界书分类与未绑定批量清理、双击正文进入编辑、扩展设置抽屉、版本自动重载。
- **1.0.4.1** 修掉移动端还能改的几处：黏性、绑定到角色或标签、筛选生成触发器这些字段的标题本身也能点开原生选择器，现在单击一律无效、双击才进编辑；黏性、冷却、延迟、组权重也支持双击改并即时保存。
- **1.0.4** 条目内的字段都加上了单击保护：文本与数字框默认只读，双击该字段才解锁，解锁后「取消 / 保存」出现在条目右侧、收藏键左边的位置，整张列表同一时刻只允许一处处在编辑状态。同时修掉浏览器缓存导致的「更新后还是旧版」：脚本版本串跟着发版号变，控制台会打印当前实际跑的构建号。
- **1.0.2** 「收藏置顶」改为覆盖整本书：以前只把当前页上的收藏条目提到前面，条目分页时收藏项在别的页就不动；现在置顶后收藏条目排在整本书最前面（第 1 页），其余条目仍按原来的排序。
- **1.0.1** 手机端弹窗改为垂直居中；键盘盖住页面时自动上移，减少被输入法遮挡的情况。
- **1.0** 正式发布。
